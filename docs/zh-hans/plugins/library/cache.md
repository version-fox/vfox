# Cache 标准库

`vfox` 为插件提供了一个简单的持久化键值缓存。在 Lua 脚本中，你可以使用 `require("vfox.cache")` 来访问它。

值以 JSON 形式保存，因此可以是字符串、有限数字、布尔值或由它们组成的 table。键是字符串（数字会转换为对应的字符串）。每次修改后缓存都会写入传给 `new` 的文件，
因此在多次运行之间依然有效。

**Usage**

```lua
local cache = require("vfox.cache")

local c, err = cache.new("/path/to/cache-file")

-- 第三个参数是以秒为单位的过期时间，-1（默认值）表示永不过期
c.set("key", { "a", "b" }, 3600)

local value = c.get("key") -- key 不存在或已过期时返回 nil；缓存文件无法读取时返回 nil 和错误信息

c.remove("key")
```

**API**

| 函数                     | 说明                                                                                                                                                                                                       |
|--------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `cache.new(path)`        | 打开保存在 `path` 文件中的缓存。`new` 不会创建文件：文件不存在时视为空缓存，第一次成功的 `c.set` 或 `c.remove` 才会写入该文件（并创建缺失的目录）。返回缓存对象，或 `nil` 和错误信息。                                                                                                                                  |
| `c.set(key, value, ttl)` | 保存 `value`。`ttl` 以秒为单位（可为小数）：`-1` 永不过期，`0` 立即过期，带过期时间的条目，其最大 ttl 随时间推移而变小，因为过期时间不能晚于 2262 年（精确的最大值见下方错误信息）。返回 `true`，或 `nil` 和错误信息。超出范围的 ttl、`-1` 以外的负数或 `NaN` 会抛出错误：`expire time must be -1 (never expires) or a number of seconds from 0 up to <最大 ttl>`。如果系统时钟早于 1970 年或距 2262 年 4 月不足一秒，则无法保存任何带过期时间的条目，错误信息会改为说明时钟超出支持范围；`-1` 不受影响。非数字的 ttl 会抛出类型错误。 |
| `c.get(key)`             | 返回值；key 不存在或已过期时返回 `nil`；缓存文件无法读取时返回 `nil` 和错误信息。                                                                                                                          |
| `c.remove(key)`          | 删除 key。返回 `true`，或 `false` 和错误信息。                                                                                                                                                             |

**错误**

无法解码的缓存文件（例如空文件或已损坏的文件）会被报告，但不会被覆盖。`cache.new` 返回 `nil` 和 `read cache "<path>": <原因>`；如果文件在 `new` 之后损坏，`c.get`、`c.set` 和 `c.remove` 也返回同样的信息。其他失败（例如在 Windows 上因其他进程占用文件而导致重命名失败）也以同样方式返回。

**限制**

当值不被允许时，`c.set` 不会保存它，而是返回 `nil` 和错误信息：

- 嵌套超过 256 层的表会被拒绝。
- 单个值写出的 JSON 限制为 64 MiB。大小按编码后的形式保守估算，不会低于实际写出的大小：`<`、`>`、`&` 等被转义的字符（各占 6 字节）以及较长的键都按转义后的大小计算，被多次引用的表每次引用都会计算一次。估算值可能略高于实际大小（每个数组元素约多 1 字节，部分控制字符也会多算），因此略低于 64 MiB 的值也可能被拒绝。
- 被多次引用的表每次引用都会写出一次。第二次及之后的引用内部所写出的值限制为 1,048,576 个（表本身不计，只计其内容）。一个两元素的表有两个值，因此对它的 524,289 次引用可以保存（524,288 次重复，共 1,048,576 个值），524,290 次则会被拒绝，而输出只有约 3 MB 的 JSON。
- 字符串、表的键以及 `key` 参数必须是有效的 UTF-8。
- 数字必须是有限的：`NaN` 和无穷大会被拒绝。
- 函数、userdata、线程、递归嵌套的表、稀疏数组以及同时包含数组键和字符串键的表会被拒绝。

`json.encode` 对普通数据没有大小限制。它的限制只针对被多次引用的表，另外还有深度限制：

- 在对同一个表的第二次及之后的引用内部，它适用于 `c.set` 相同的 1,048,576 个值的限制，另外还有一个独立的限制：这些重复内容估算写出的字节数不超过 64 MiB。重复引用之外的内容不受限制，因此没有共享表的数据永远不会被限制。这与 `c.set` 不同，`c.set` 的 64 MiB 限制针对整个值。
- 嵌套超过 10,000 层的表会使它返回 `nil` 和错误信息（`exceeded max depth`，即 Go `encoding/json` 的嵌套限制）。嵌套远深于此的表处理得不好：编码可能耗时很长，或因栈溢出使进程崩溃。这与 cache 模块出现之前相同。
